# i18n Routing Planner

## Role
Planning agent that designs the Next.js App Router internationalization routing layer. Decides between locale-prefix routing (`/[locale]/...`), domain routing, or cookie-based routing, and emits a configuration plan consumed by `i18n_runtime_integrator.md`.

## Contract

### Receives
- `i18n_requirements`: from `i18n_requirements_analyst.md`
- `design_blueprint`: from `figma_design_analyst.md`
- `key_registry`: from `i18n_key_extractor.md`

### Returns
- `routing_plan`: dict — {
  - `strategy`: enum (`prefix`, `domain`, `cookie`, `subpath`)
  - `locales`: list[str]
  - `default_locale`: str
  - `locale_prefix`: enum (`always`, `as-needed`)
  - `middleware_config`: dict — matcher, redirects, locale detection headers
  - `file_layout`: dict — paths for `middleware.ts`, `i18n/routing.ts`, `app/[locale]/layout.tsx`
  - `nav_rewrite_rules`: list of { `from`, `to`, `locale` }
}
- `next_phase_hint`: enum (`planning`, `execution`, `result`)

### Side effects
- No filesystem writes; output feeds `i18n_runtime_integrator.md`

## Decision Flow

1. **Select strategy** — `prefix` by default for static sites generated by the Figma pipeline; `domain` only if explicit domain mapping provided; `cookie` as secondary signal when mixed routing requested.
2. **Decide locale prefix mode** — `as-needed` when default locale should not show `/en/`; `always` when strict locale parity required (recommended for SEO parity).
3. **Map route files** — plan `src/app/[locale]/page.tsx`, `src/app/[locale]/layout.tsx`, `src/i18n/routing.ts`, `src/i18n/config.ts`, `middleware.ts` at project root.
4. **Generate matcher** — middleware matcher excludes static files, API routes, `_next/`, and well-known paths.
5. **Handle root redirect** — if prefix mode with `as-needed`, root `/` redirects to browser-detected locale or default.
6. **Produce nav rewrite rules** — for internal prototype navigation links from `figma_map_interactions`, rewrite to locale-prefixed paths.
7. **Return plan** with hint `execution` when plan is complete, `planning` if domain strategy needs DNS info.

## Failure Modes

| Condition | Response |
|---|---|
| Single locale and no prefix requested | Return `strategy=cookie`, `locale_prefix=as-needed`; no middleware needed |
| Domain strategy without domain list | Fall back to `prefix`; emit warning |
| Middleware conflict with existing backend API | Exclude `/api/*` and add rewrite rule; log to `audit_logger.md` |
| Locale code invalid for URL path | Normalize to lowercase and replace `_` with `-`; warn if changed |
