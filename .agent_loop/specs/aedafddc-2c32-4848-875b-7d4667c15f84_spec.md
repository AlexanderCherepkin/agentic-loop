# Спецификация — Resume task 2026-07-25

## Goal

1. Реализовать `/journey` — легковесный локальный read-only визуализатор радиального графа на основе `memory/wiki/` и `SKILL.md`/`/learn`.
2. Укрепить фундамент: закрыть критические zero-coverage модули, особенно `runtime/sandbox/engine.py`, `runtime/code_review/engine.py`, `runtime/engine/ponytail_optimizer.py` и core Figma pipeline (`figma-agent-core/conductor.py`, `agent.py`, `bootstrap.py`), затем покрыть `runtime/skill_integration/` и `runtime/wiki/`.

## Scope — In

### A. `/journey` radial memory graph
- Новый slash-команда `/journey` в CLI/skill surface.
- Локальный HTML-отчёт/веб-роут, генерируемый без внешних зависимостей (предпочтение SVG, fallback D3.js).
- Парсинг `memory/wiki/*.md` для извлечения перекрёстных ссылок `[[...]]`.
- Парсинг `.claude/skills/*/SKILL.md` и истории `/learn` для таймлайна навыков.
- Радиальная визуализация: узлы — концепции/навыки, рёбра — связи `[[...]]`; таймлайн — кольцами/слоями по дате.
- Read-only доступ к `memory/wiki/` и `.claude/skills/` с жёсткими границами `ensureWorkspacePath()` / `MCPPathGuard`.
- CLI-интеграция: команда открывает сгенерированный HTML в браузере (локально, без хостинга самого агента).

### B. Test suite hardening
- Прогон полного `pytest --cov` для актуального среза.
- Приоритет: 4 критических zero-coverage модуля:
  - `runtime/sandbox/engine.py` — изоляция произвольного кода.
  - `runtime/code_review/engine.py` + `runtime/code_review/diff_engine.py` — применение патчей.
  - `runtime/engine/ponytail_optimizer.py` — prompt-инжектор.
  - `figma-agent-core/conductor.py`, `figma-agent-core/agent.py`, `figma-agent-core/bootstrap.py` — core pipeline.
- Второй волной: тесты для `runtime/skill_integration/` и `runtime/wiki/`.
- Цель: повысить total coverage выше 64.54% и ликвидировать наиболее рисковые слепые зоны.

## Scope — Out

- Не публикуем `/journey` как внешний сайт или публичный endpoint.
- Не модифицируем core text memory — визуал только read-only.
- Не проводим database migrations, deploy, `git push` без отдельного human approval.
- Не переписываем полностью `figma-agent-core` — только покрытие core pipeline тестами.
- Не добавляем тяжёлые frontend-фреймворки (React/Next.js для `/journey` — out; SVG/D3 + vanilla JS only).

## Key Decisions

1. **Стек `/journey`**: SVG-first generated HTML, optional D3.js via CDN только в локальный HTML-файл (никаких npm-зависимостей в проекте).
2. **Данные**: парсим `[[...]]` вручную по markdown-файлам; таймлайн навыков берём из frontmatter `date` или имени файла SKILL.md.
3. **Безопасность**: все пути нормализуются через `ensureWorkspacePath()` / `MCPPathGuard`; запись в memory/wiki/ запрещена.
4. **Тестовая методология для критических модулей**: property-based / adversarial tests для sandbox, patch-applier тесты для code_review, prompt-injection adversarial suite для ponytail_optimizer, интеграционный smoke-test для figma core pipeline.
5. **Порядок работы**: сначала тестовый харднинг (фундамент), затем `/journey` (feature на чистом фундаменте), затем тесты для новых модулей.
