# /learn-from-source

> Превращает источник опыта в постоянный навык Claude Code. Ты даёшь ссылку, путь к
> документу или описание процесса — скилл разбирает его в пошаговый алгоритм, оформляет
> как SKILL.md и сохраняет под `.claude/skills/`.
>
> Работает руками через файловую систему навыков Claude Code: команды `/learn` и `/journey`
> из некоторых агентских сред (Hermes и др.) здесь нет — они либо не реализованы, либо
> действуют как обёртки над тем же механизмом SKILL.md. Поэтому этот скилл использует
> прямой путь: написать SKILL.md и положить его в `.claude/skills/<name>/`.
>
> Победа → навык: после удачного разговора можно вручную вызвать этот скилл и сказать
> «сохрани этот чат как навык», он упакует пройденный путь с gotcha-секцией.

⚠️ Скилл **никогда не перезаписывает** существующий `.claude/skills/<name>/SKILL.md`
без явного «да». Перед записью он показывает результат и путь.

---

## Когда срабатывать

Активируй, когда пользователь просит превратить что-то в навык:
- «сделай навык из этого источника / статьи / ролика / чата»
- «преврати в SKILL.md»
- «запакуй удачный разговор в навык»
- «вытащи пошаговый процесс и сохрани как скилл»
- явный вызов: `learn-from-source: <источник>`

**НЕ срабатывай:**
- если пользователь просто просит резюме, конспект или TL;DR — это не навык;
- если источник не дан и не упомянут, а просят «сделай скилл про X» — сначала нужен источник опыта;
- если просят обновить существующий скилл — это другой механизм (merge/revision), не `learn-from-source`.

## 🧠 ГЛАВНОЕ: структура навыка Claude Code

Файл навыка — это `SKILL.md` в папке `.claude/skills/<name>/`.

Фронтматтер (обязателен):
```yaml
---
name: <kebab-case-имя>
description: "<одно предложение: когда использовать, триггер, ограничения>"
---
```

Тело:
- `# /name` — заголовок и один абзац «для чего».
- `## Когда срабатывать` — триггеры и анти-триггеры.
- `## Decision Flow` или `## Алгоритм` — нумерованные шаги, которые агент может повторить.
- `## Гарды` или `## Failure Modes` — что делать, когда что-то идёт не так.
- Опционально: `## Грабли`, `## Примеры`, `## Победа → навык`.

## 🛡 ГАРДЫ (выполнять ВСЕГДА)

### Гард 1 — Источник должен быть конкретным
- URL — ок, но Claude Code не всегда может открыть внешний сайт; если не получилось,
  попроси пользователя скопировать текст или вставить описание процесса.
- Путь к локальному файлу — ок, читаем через Read.
- Описание процесса из текущего чата — ок, но только если есть удачный пройденный путь.
- «Сделай скилл про X» без источника — **не ок**, нужен материал для экстракции.

### Гард 2 — Никогда не перезаписывай без «да»
- Перед записью проверь `.claude/skills/<name>/SKILL.md`.
- Если файл существует — покажи его и спроси: «Перезаписать?».
- Молчание, «давай», «как знаешь», «вроде ок» — **не являются утверждением**.
- Если пользователь не отвечает явно `да` / `ok` / `согласен` — **не пиши файл**.

### Гард 3 — Проверь, что новый навык не дублирует существующий
- Просмотри `.claude/skills/*/SKILL.md`.
- Если тема совпадает — предложи дополнить существующий навык вместо создания нового.

### Гард 4 — Разделяй факты источника и личные догадки
- Если источник утверждает что-то про поведение внешнего продукта (Hermes, Claude Code,
  API и т.д.), и ты не можешь это верифицировать — добавь в SKILL.md оговорку:
  «информация предоставлена источником; проверь актуальность перед применением».

## 📋 АЛГОРИТМ

### Шаг 1 — Получить источник
- Спроси пользователя: ссылка, путь к файлу, или текущий чат.
- Если URL — попробуй WebFetch. Если не удалось — попроси текст.
- Если путь — Read.
- Если «этот чат» — используй историю текущей сессии.

### Шаг 2 — Извлечь повторяемый процесс
Из источника вытащи:
- какая проблема решается;
- когда навык нужен / не нужен;
- пошаговый порядок действий;
- ограничения, границы, анти-паттерны;
- типичные ошибки (gotchas) и как их избежать.

### Шаг 3 — Подобрать имя и проверить конфликты
- Имя — kebab-case, короткое, понятное.
- Проверь `.claude/skills/<name>/SKILL.md`.
- При конфликте спроси: переименовать, объединить или отменить.

### Шаг 4 — Составить черновик SKILL.md
Структура:
```markdown
---
name: <name>
description: "<триггер и назначение>"
---

# /name

> <один абзац сути>

## Когда срабатывать

- ...

**НЕ срабатывать:**
- ...

## Decision Flow

1. ...
2. ...

## Гарды / Failure Modes

| Условие | Действие |
|---|---|
| ... | ... |

## Грабли

| Симптом | Что делать |
|---|---|
| ... | ... |
```

### Шаг 5 — Показать черновик и путь
- Напечатай полный SKILL.md.
- Укажи путь, куда он будет записан.
- Спроси явное «да».

### Шаг 6 — Записать файл
- Создай директорию `.claude/skills/<name>/` при необходимости.
- Запиши SKILL.md.
- Обнови `MEMORY.md` в корне памяти пользователя (если проект связан с memory-индексом).

### Шаг 7 — Опционально: победа → навык
- Если источником был удачный чат — добавь секцию `## Победа → навык` с кратким
  описанием, какой именно чат был упакован и какие gotcha из него выжаты.

## 🪤 ГРАБЛИ

| Симптом | Что делать |
|---|---|
| Источник недоступен | Попроси пользователя скопировать текст в чат или сохранить в файл |
| Черновик получился слишком общим | Вернуться к источнику, вытащить конкретные шаги и анти-паттерны |
| Имя навыка занято | Предложить ближайшее свободное имя или merge существующего |
| Пользователь не говорит явное «да» | Не писать файл; оставить черновик в чате для доработки |
| Источник содержит непроверяемые утверждения | Добавить оговорку и не выдавать их как официальные факты |

---

## ✅ Что этот скилл гарантирует

- Извлечёт из источника повторяемый процесс, а не просто конспект.
- Оформит его в корректный SKILL.md с фронтматтером Claude Code.
- Не перезапишет существующий навык без явного согласия.
- При непроверяемых фактах добавит оговорку, а не выдаст их за истину.
- Покажет результат перед записью.
