# Premium Design Skill (Anti-Slop Engine)

Этот скилл активируется автоматически при генерации UI и переводит модель из режима «медианной генерации по умолчанию» в режим строгого премиального дизайна.

При старте любой UI-задачи:
1. Загрузи проектную память: `[[forbidden-fonts]]`, `[[allowed-fonts]]`, `[[typography-standards]]`, `[[premium-design-rules]]`, `[[design-source-triad]]`.
2. Сформируй предложение по шрифтам и визуальному направлению, **не спрашивая пользователя напрямую**, но явно представь его для подтверждения.
3. Если пользователь дал референс (URL бренда/конкурента или файл `DESIGN.md`), используй `tooll_subagents/planning/design_reference_extractor.md` для выжимки логики в DTCG-brief.
4. После подтверждения сгенерируй `DESIGN.md` по шаблону `templates/DESIGN.md` и `design_tokens.json` в формате DTCG (W3C Design Tokens Community Group) через `runtime/premium_design/DtcgTokenEngine`.
5. Убедись, что `refactoring_ui_scores.aggregate` ≥ 0.7 и `anti_slop.verdict` = `pass`.
6. Только затем переходи к генерации UI-кода.

## 01. Входная конфигурационная матрица

Перед генерацией UI инициализируй переменные:

| Параметр | Диапазон | За что отвечает | Anti-Slop предохранитель |
|---|---|---|---|
| `VARIANCE` | 0.0 — 1.0 | Отклонение от медианы. 0.0 — жёсткий Swiss минимализм, 1.0 — брутализм/ретрофутуризм. | Блокирует «Hero + 3 карточки» при > 0.4. |
| `DENSITY` | 0.0 — 1.0 | Плотность. 0.0 — просторный Editorial, 1.0 — компактный Dashboard/TUI. | Паддинги — динамическая функция, не хардкод `p-6`. |
| `MOTION` | 0.0 — 1.0 | Сложность микродинамики. | Разрешены только compositor-friendly `transform`/`opacity`. |

## 02. Спецификация 44 запретов (Anti-Slop QA Rules)

Любое нарушение в сгенерированном коде — признак slop-дизайна и повод для принудительной перегенерации.

### А. Типографика и контент (1–8)
1. **БАН шрифтов по умолчанию.** Запрещены Inter, Roboto, Open Sans, Arial, Space Grotesk, Helvetica, Segoe UI, San Francisco, Myriad Pro, Calibri, Verdana, Century Gothic. Использовать характерные пары из `[[allowed-fonts]]`.
2. **БАН плоского серого текста.** Запрещён `text-gray-500` на белом фоне. Использовать контекстные палитры с примесью основного тона.
3. **БАН статического интерлиньяжа.** Запрещён одинаковый `leading-normal` для всех размеров. Заголовки — `leading-tight`/`leading-[0.9]`, мелкий текст — увеличенный интерлиньяж.
4. **БАН дефолтного трекинга.** Запрещён `uppercase` без явного `tracking-wider`/`tracking-widest`.
5. **БАН жирных начертаний без компенсации.** Запрещён `font-bold` для заголовков > 48 px без Display-начертания. Использовать `font-medium`/`font-semibold` с уменьшенным `letter-spacing`.
6. **БАН произвольного vw-респонсива.** Запрещены `text-[4vw]`. Использовать Tailwind-брейкпоинты или `clamp()`.
7. **БАН бесконечной длины строки.** Параграфы ограничивать `max-w-prose`/`max-w-2xl`.
8. **БАН сиротствующих слов.** Использовать `&nbsp;` перед союзами и короткими словами в заголовках.

### Б. Сетка, композиция и скелет (9–17)
9. **БАН трёхколоночного шаблона.** Запрещены 3 одинаковые карточки фич. Использовать Bento-сетки или асимметрию.
10. **БАН центрированного Hero-slop.** Запрещён «центрированный заголовок → серый подзаголовок → кнопка по центру». Сдвигать акценты, использовать split-экран или Editorial-обложки.
11. **БАН бесконечного вертикального стека.** Секции должны чередовать визуальный вес.
12. **БАН разделителей-костылей.** Запрещены пустые `<hr>` как единственный способ зонирования.
13. **БАН бесконтрольного `w-full`.** Контентные блоки ограничивать `max-w-7xl`/`max-w-[1440px]` `mx-auto`.
14. **БАН центрирования сложных форм.** Поля ввода и строки таблиц выравниваются по левому краю.
15. **БАН одинаковых паддингов везде.** Внешние отступы ≥ в 2–3 раза больше внутренних.
16. **БАН симметричного Split-экрана.** Запрещён `grid-cols-2` 50/50. Использовать 40/60 или 35/65.
17. **БАН дублирования структуры карточек.** Карточки разного назначения не должны выглядеть одинаково.

### В. Тени, границы и свечения (18–25)
18. **БАН дефолтных теней.** Запрещены `shadow-md`/`shadow-lg`/`shadow-xl`. Использовать многослойные кастомные тени с малой непрозрачностью.
19. **БАН градиентных клякс (Blob Slop).** Запрещены размытые фиолетовые/розовые круги в углах.
20. **БАН грязного Glassmorphism.** Запрещён бездумный `backdrop-blur-md bg-white/30`. Требуется тонкая граница, заградительный слой и `backface-visibility`.
21. **БАН плоских чёрных границ в Dark Mode.** Запрещён чистый чёрный или `border-neutral-800`. Использовать глубокие оттенки с лёгким свечением.
22. **БАН одинакового скругления.** Внутренние элементы должны иметь меньший радиус, чем внешний контейнер.
23. **БАН длинного градиентного текста.** Градиент допустим максимум на одном ключевом слове.
24. **БАН слепых оверлеев.** Текст поверх изображений требует scrim/overlay по WCAG.
25. **БАН сплошных ярких рамок.** Яркая рамка карточек допустима только в нео-брутализме.

### Г. Цвет, контраст и доступность (26–32)
26. **БАН безжизненного монохрома.** Запрещён чистый `bg-neutral-100`/`bg-zinc-900`. Использовать тонированные оттенки (warm gray, cool gray, slate с примесью).
27. **БАН сырых сигнальных цветов.** Запрещены `bg-red-500`/`bg-blue-500` в чистом виде. Мапить на приглушённые палитры токенов.
28. **БАН нарушения контраста WCAG 2.2.** Минимум 4.5:1 для обычного текста, 3:1 для крупного.
29. **БАН скрытия Focus-ring.** Запрещён `focus:outline-none` без кастомного заметного фокуса.
30. **БАН цветового хаоса.** Более 3 активных цветов на экране запрещены.
31. **БАН завязки логики только на цвет.** Статус дублировать иконкой, текстом или формой.
32. **БАН хардкода прозрачности текста.** Запрещено `text-black/40`, если падает контраст.

### Д. Моушен, анимация и интерактив (33–39)
33. **БАН анимации геометрических свойств.** Запрещены `width`, `height`, `margin`, `padding`, `top`/`left` в анимациях. Только `transform` и `opacity`.
34. **БАН тотального `transition-all`.** Указывать явные свойства: `transition-[transform,opacity]`.
35. **БАН линейного тайминга.** Запрещены `ease-in-out`/`linear`. Использовать кастомные Bézier (например, `cubic-bezier(0.16, 1, 0.3, 1)`) или springs из `motion.dev`.
36. **БАН игнорирования `prefers-reduced-motion`.** Сложная анимация должна отключаться или превращаться в fade-in.
37. **БАН бесконечных циклов.** Бесконечное пульсирование запрещено, если это не критичный индикатор внимания.
38. **БАН Layout Shift при ховере.** Запрещены hover-эффекты, увеличивающие размер и сдвигающие соседей.
39. **БАН анимации скрытых элементов.** Использовать `content-visibility: auto` или демонтировать компоненты.

### Е. Архитектура кода и семантика (40–44)
40. **БАН магических инлайнов.** Запрещены `p-[23px]`, `w-[412px]`. Все размеры — из сетки `DESIGN.md`.
41. **БАН кривых bounding-box у иконок.** Иконки одного ряда — в фиксированных квадратных контейнерах.
42. **БАН монолитных файлов UI.** Декомпозировать на атомарные компоненты с типизацией пропсов.
43. **БАН слепых заглушек изображений.** Запрещены пустые `<img src="" />`. Использовать `aspect-*` и CSS-плейсхолдер.
44. **БАН div-супа.** Использовать семантику HTML5: `<main>`, `<section>`, `<article>`, `<nav>`, `<aside>`, `<footer>`.

## 03. Первоисточники методологии

Этот skill — не магия, а применение трёх проверенных источников:
- **Refactoring UI** (Adam Wathan + Steve Schoger, refactoringui.com) — логика scale contrast, семантической палитры, elevation-теней, rhythmic spacing, type pairing и полноты состояний. В проекте закреплена в `runtime/premium_design/refactoring_ui_rules.py` — 6 deterministic checks (`scale_contrast_score`, `palette_semantic_score`, `shadow_elevation_score`, `spacing_rhythm_score`, `type_pairing_score`, `state_completeness_score`) и hard gate `aggregate >= 0.7` в `DtcgTokenEngine.generate()`.
- **Anthropic Skills** (agentskills.io) — открытый стандарт lazy-loaded skills, который держит этот skill в памяти только при UI-задачах. В проекте skill прописан в `claude.json` (`designSync.skills`, `hooks.pre_generation` / `hooks.post_generation_audit`) и экспортирован в Open Design через `open-design-integrator.mjs`.
- **awesome-design-md** (github.com/VoltAgent/awesome-design-md) — MIT-коллекция из 73 реальных `DESIGN.md` (Stripe, Apple, Tesla, Claude, Figma и др.), которые превращают «сделай красиво» в жёсткий контракт. В проекте разобраны агентом `.agent_loop/tooll_subagents/planning/design_reference_extractor.md`, а собственный контракт живёт в `templates/DESIGN.md`.

Подробная связка источников описана в проектной памяти [[design-source-triad]].

## 04. Алгоритм исполнения

При генерации UI-кода:
1. Создай или обнови `DESIGN.md` — зафиксируй направление, шрифты и токены.
2. Сгенерируй `design_tokens.json` в формате DTCG через `runtime/premium_design/DtcgTokenEngine`.
3. Проверь токены через `runtime/premium_design/refactoring_ui_rules.py` — aggregate score должен быть ≥ 0.7.
4. Сгенерируй код компонентов с Tailwind CSS; используй `motion.dev`, если `MOTION > 0`.
5. Проверь код по AST/regex на любой из 44 запретов.
6. При нарушении — запусти раунд исправления: `[Anti-Slop QA]: правило #X. Исправление...`
